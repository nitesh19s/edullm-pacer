What is the Pythagorean theorem and when does it apply?
Just now
The Pythagorean theorem states that in a right-angled triangle, the square of the hypotenuse equals the sum of the squares of the other two sides: c² = a² + b², where c is the hypotenuse.

It applies whenever a triangle has one angle exactly equal to 90°. A quick check: if three sides satisfy a² + b² = c², the triangle is right-angled (converse theorem). Common integer triples include (3, 4, 5) and (5, 12, 13).

Research Experiments

Track and compare RAG system experiments for your research

How to Run Experiments — PACER RAG benchmark workflow
1

Create an Experiment

Click New Experiment. Give it a descriptive name that identifies the chunking strategy being tested (e.g., "PACER-bge-large-900q"). Add tags like pacer, bge-large, ncert for easy filtering later.

2

Index NCERT Data

Click Index NCERT Data to chunk and embed the corpus with the currently configured strategy. This populates the vector store. Check Vector Store count in Statistics — should reach ~16,369 for PACER or ~8,581 for Fixed-1024.

Configure chunking strategy in Smart Chunking tab before indexing.
3

Start a Run

Select your experiment from the list, then click Start Run. Each run captures a snapshot of parameters: chunking method, chunk size, overlap, embedding model, and retrieval top-k. The run timer begins.

4

Execute Benchmark Queries

Go to RAG Chat and run your evaluation queries — or use the backend Python script to run the full 900-query NCERT benchmark automatically:

python scripts/run_benchmark.py --queries data/queries/ncert_900.json --out results/run_$(date +%Y%m%d).csv
The benchmark measures MRR, nDCG@10, CAS and latency per query automatically.
5

End Run & Record Metrics

Click End Run. Enter the metrics from the benchmark output:

MRR Mean Reciprocal Rank nDCG@10 Normalised DCG CAS Curriculum Alignment Score Latency Query time in ms
6

Compare Runs

Click Compare Runs to open the comparison modal. Select 2+ runs to see a side-by-side parameter and metrics table with visualisations. Export results as JSON for paper tables.

PACER results are already in PACER Results tab — use this for new ablation conditions.

PACER Experiment Results

Pedagogy-Aware Adaptive Chunking — live paper tables & CAS metrics

PACER vs Baselines — Retrieval Metrics

This table compares 8 chunking strategies across 798 evaluated NCERT queries (Math: 182, Science: 294, Social Science: 322 — Grades 7–12) using two embedding models. Metrics are MRR (Mean Reciprocal Rank) and nDCG@10 (normalised Discounted Cumulative Gain).

  • PACER (bge-large): MRR = 0.9241, nDCG@10 = 0.9208 — matches the best fixed strategy on this homogeneous corpus.
  • Best MRR overall: Recursive-512 + bge-large (0.9354) — but 2.5× slower (214 ms vs 87 ms) and no curriculum awareness.
  • PACER routing finding: On the uniform NCERT corpus (all TEXTBOOK_CHAPTER), PACER's router correctly selects the EDUCATIONAL chunker for 100% of documents — matching the oracle fixed baseline. This is a principled behaviour, not a limitation.
  • Embedding impact: bge-large-en-v1.5 outperforms all-MiniLM-L6-v2 by +0.03–0.04 MRR across all conditions.

Ablation Study — Effect of Router & Boundary Post-processor

The ablation study isolates the contribution of each PACER component by removing one at a time and measuring the drop in retrieval quality. Three ablation conditions are tested against the full PACER system:

  • A1 — No Router: All documents are chunked with a single fixed strategy (educational_2000). Measures the value of adaptive document-type routing.
  • A2 — No Boundary Post-processor: Chunks are not refined at pedagogical boundaries (section headings, concept breaks). Measures the value of boundary-aware splitting.
  • A3 — No CAS: Retrieval ranking ignores curriculum alignment score. Measures the value of pedagogical re-ranking.
  • PACER-Full: All components active — MRR = 0.9241, nDCG@10 = 0.9208.

Ablation runs are pending — results will appear here after execution on Colab.

Curriculum Alignment Score (CAS)

CAS is PACER's novel pedagogical metric measuring how well retrieved chunks align with the student's curriculum context. It is a weighted sum of three dimensions:

  • grade_match (α = 0.45): Whether the retrieved chunk is from the same grade band as the query (Middle / Secondary / Higher Secondary). Highest weight — wrong grade content is actively harmful.
  • prereq_preservation (β = 0.40): Whether prerequisite concepts appear before advanced ones within retrieved chunks, preserving learning order.
  • bloom_alignment (γ = 0.15): Whether the Bloom's taxonomy level of the chunk matches the cognitive demand of the query (recall vs. analysis vs. synthesis).

Weights were calibrated from Fleiss κ inter-rater agreement across three LLM judges. bloom_fit showed the weakest agreement (κ = 0.439), justifying its lower weight γ = 0.15.

CAS range across all conditions: 0.644 – 0.677. Recursive-512 scores highest (small chunks preserve grade/concept boundaries); PACER scores 0.651 on the uniform NCERT corpus.

Latency — Query Response Time

End-to-end query latency (ms) measured over 798 evaluated queries per condition. Latency includes embedding lookup + FAISS nearest-neighbour search + BM25 scoring + RRF fusion. Lower is better.

  • Fastest: Fixed-1024 + MiniLM (49 ms) — fewest chunks, smallest embedding model.
  • PACER + bge-large (87 ms): Recommended config. Adds ~28 ms overhead over Educational-2000 for document classification and boundary post-processing — acceptable for educational platforms where answer quality matters more than raw speed.
  • Slowest: Recursive-512 + bge-large (214 ms) — 36,981 chunks means a much larger FAISS index to search.
  • bge-large vs MiniLM: bge-large adds ~30–80 ms per query due to the larger 1024-dim embedding space.

CAS Validation — Inter-rater Agreement

To validate the CAS metric, three LLM judges (Groq Llama-3.3-70B, Groq Llama-3.1-8B, Gemini 2.5 Flash) independently rated 150 query–chunk pairs on each of the three CAS dimensions. Agreement is measured using Fleiss κ (multi-rater) and Pearson r (pairwise).

  • prereq_preservation (κ = 0.611): Crosses the κ ≥ 0.6 threshold — substantial agreement. Validates using this dimension at β = 0.40.
  • grade_match (κ = 0.587): Just below threshold but strong Pearson r = 0.755. Grade boundaries are relatively clear to all judges.
  • bloom_fit (κ = 0.439): Weakest agreement — Bloom level assignment is inherently subjective. Justifies the reduced weight γ = 0.15.
  • Overall mean κ = 0.545 — moderate agreement across all dimensions, consistent with published CAS/rubric validation studies.

Human rater calibration is pending (target κ ≥ 0.6 on all dimensions).
